Best architecture
For your use case, browser-use/browser-use is the best fit for agentic browser control, while unclecode/crawl4AI is the best fit for large-scale crawling/extraction pipelines. Browser Use is more “task agent over browser,” whereas Crawl4AI is more “crawl/extract/normalize pipeline,” which makes them complementary rather than redundant.

Reusable modules
The highest-value reusable modules are:

Browser session and profile reuse from Browser Use.

Tool/action abstraction and custom tool registration from Browser Use.

Async crawling, deep crawl state, and recovery loops from Crawl4AI.

Hook-based crawl customization from Crawl4AI.

Structured extraction and markdown-generation pipelines from Crawl4AI.

Website ingestion and map/scrape primitives from Firecrawl.

Python SDK integration patterns from firecrawl-py.

Technical fit
For Google Maps and local lead generation, the most directly reusable repo in this set is gosom/google-maps-scraper, but it needs star-count verification before you make it a core dependency. For LinkedIn enrichment, pratik-dani/LinkedIn-Scraper is relevant functionally, but it does not satisfy your 1000+ star requirement from the evidence I could verify here. For Instagram/Facebook scraping, the social-media-profile-scrapers collection is the cleanest Apache-licensed starting point, but it is not a mature 1000+ star codebase.

Recommendation
If you want the most production-ready foundation, build around:

Browser Use for interactive automation and authenticated workflows.

Crawl4AI for crawling, extraction, and normalization.

Firecrawl for web-context ingestion APIs where AGPL is acceptable.

Add platform-specific scrapers only where needed for Maps, LinkedIn, and social enrichment.
